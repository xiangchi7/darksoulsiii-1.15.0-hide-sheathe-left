# 停放 dummy（parking dummy）版 HideSheathedLeft — 安装与实测说明

这一版把「隐藏收起状态的左手道具」的实现方式换掉了：

| | 旧版 (v1.0.0) | 这一版 |
|---|---|---|
| 怎么写参数 | 把 `leftHang_0..3`（成对武器还有 `right_1..3`）写成 `0xFFFF`（= 无效挂点） | 默认写 **382**：模型补丁给**每一个角色模型**都追加了这个挂点（在各自正下方 1000 米），因此玩家和 NPC 都会把这件道具放到看不见的地方（`383` 备用，ini 可切换） |
| 引擎行为 | 无效挂点 → 退化/NaN 矩阵 → **黑三角 + 全屏闪烁** | 正常矩阵 → 模型只是被放在角色下方 1000 米处，永远在视锥外被剔除 |
| 判定条件 | 引擎按姿态决定（不变） | 引擎按姿态决定（不变，取消双持立刻恢复） |
| 作用范围 | 参数表是 PC/NPC 共用 | 同样共用；但**新增/挪动的挂点在玩家专用模型里**（`c0000.chrbnd.dcx`） |

两个改动：

1. `chr\*.chrbnd.dcx`：给**全部 165 个角色模型**各追加两个挂点 `382` / `383`
   （父骨骼 `0`、位置 `(0, -1000, 0)`），**不改动任何原版挂点** —— 工具在写入前会先验证
   骨骼表 / 材质 / 网格 / 缓冲布局完全没变、原挂点条目一条没动，否则那个文件原样保留。
   于是参数指向 382 时：
   * **玩家**：道具被放到 1000 米下方 → 看不见（与以前一致）；
   * **NPC**：同样解析到有效挂点 → 道具也在它下方 1000 米处 → **看不见**，
     **不会穿模、不会被缩放变形、也不会出现黑三角**（这就是对"NPC 通道"的解法）。

   校验（都在本机实跑过）：
   * SoulsFormats 结构对比（以玩家模型为例）：384 个挂点（原版 382），改动**只有**末尾新增 382/383，
     原版 382 条一条没动（工具报 `dummy entries changed: 0`），骨骼表摘要完全一致，包内**只有** `c0000.flver` 变化；
   * 全量扫描 `parts\`（2344 个文件、2224 个含 FLVER）与所有角色模型 `chr\*.chrbnd.dcx`（165 个）：
     **没有任何部件占用 382 / 383**（部件里最大挂点 id 890）；随后给 165 个角色模型全部追加了这两个挂点
     （`patched=164 already-had=1 failed=0`，328 个挂点；每个文件写入前都做了结构校验）；
   * "撞号"这条风险已闭环。
2. `HideSheathedLeft.dll`：`0xFFFF` 变成 ini 里的 `HidePoly`（默认 `220`，可切 `382`/`383`，`-1` 回退旧行为）；
   并新增 `PairedFields`，决定"右手单持成对武器时隐藏哪些模型"（默认 `1,2,3`；`1` = 只藏副手刀刃、保留刀鞘）。

**为什么可以确信"挂点编号空间 = 模型挂点表"**（这一轮实机内存读出来的证据）：把 mod 关掉、让引擎把原值写回后，dump 全部 91 行参数 —— 原版取值（0 除外）**全部**正好等于 `c0000.flver` 里某个挂点的 `ReferenceID`，位置也完全对得上：

| 字段 | 原版典型值 | 对应挂点位置（模型空间） | 含义 |
|---|---|---|---|
| `right_0` / `left_0` | 20 / 21 | `(-0.59, 0.96, 0.03)` / `(+0.59, 0.96, 0.03)` | 左右手（镜像对） |
| `rightHang_0` / `leftHang_0` | 30 / 31 | `(+0.29, 1.02, -0.12)` / `(-0.26, 1.04, -0.11)` | 背后两侧（镜像对，z<0 = 身后） |
| `both_0` / `leftBoth_0` | 24 | `(-0.59, 0.96, 0.02)` | 双手握持 |
| `leftHang_1` / `right_1` | 61 / 62 | `(+0.29, 0.96, -0.13)` / `(-0.26, 0.98, -0.11)` | 另一种背后挂法 |

反过来当"骨骼下标"解释就说不通（31 会是 `R_Foot`、24 会是腰上的 `L_Wepon_Case`）。所以 `docs/骨架编号表.txt` 里"这些字段索引骨骼表"的旧结论是**错的**（编号恰好和武器盒骨骼重名才误导了那一轮），"停放挂点"这个做法正落在正确的空间里。

原始 dump（可自行核对）：`dumps/vanilla.json`（引擎原值）、`dumps/active.json`（mod 生效值）、`docs/dummies-vanilla.txt` / `docs/dummies-parked.txt`（挂点表改动前后）。

## 安装 / 还原

```powershell
# 关掉游戏
powershell -ExecutionPolicy Bypass -File install.ps1
powershell -ExecutionPolicy Bypass -File install.ps1 -Status     # 看装了什么
powershell -ExecutionPolicy Bypass -File restore.ps1             # 还原（按 manifest 逐字节回放）
powershell -ExecutionPolicy Bypass -File restore.ps1 -DryRun     # 只报告，不改动
```

install.ps1 在覆盖任何文件前，先把它**逐字节**复制到 `<游戏>\.hsleft-backup\<同样的相对路径>`，
并把「原来存不存在 / 改动前后的 SHA-256 / 大小 / 备份路径 / 新建了哪些目录」全部写进
`<游戏>\.hsleft-manifest.json`。restore.ps1 回放这份 manifest：原文件逐字节放回并校验哈希，
安装时新建的文件（dll / ini / `chr\c0000.chrbnd.dcx`）删除，新建目录空掉后删除。
如果某个文件已经不是我们装的那一个（你换过、别的 mod 换过），restore 会停下来说明情况
（退出码 1）而不是覆盖别人的东西，并保留 manifest 与备份以便重试，`-Force` 才继续。

**为什么必须留原生副本**：只把挂点删掉的「结构还原」不等于原字节——BND4 会重新序列化、
DCX 会重新压缩（实测：删掉挂点后 43,792 -> 47,220 字节，解压后的载荷完全一致）。
1.0.4 及更早装的没有 manifest，restore.ps1 不会乱猜；确实要结构还原时加 `-AllowLegacy`。

`xinput1_3.dll.dkp-off` 属于旧流程（1.0.4 的改名备份）；现在这一类文件也走
`.hsleft-backup\`，restore 会把原来的 `xinput1_3.dll` 原样放回。
**注意**：这一版的 ini 里 `ExtraMods=` 是空的——之前那份 DKP 加载器在 1.15.0 上会让游戏启动即崩（见 `ds3-test-log.txt`），需要它的话自己填回去。

## 进游戏怎么验收

先确认日志：游戏目录里的 `HideSheathedLeft.log` 应该有

```
config: HideLeftHang=1 HidePairedOffhand=1 PairedFields=111 IntervalSeconds=1 Log=1 HidePoly=220
applied N field write(s) over M row(s) in K table(s)
```

装备：右手一把普通直剑，左手一面小盾（左手道具要"看得见"才好判断）。

| # | 操作 | 期望 |
|---|---|---|
| 1 | 单持站着不动 | 盾在**左手**，正常显示（不能有黑三角/闪烁） |
| 2 | 按双持键（右手双持） | 盾**完全看不到**（背上、腰上都不应该有） |
| 3 | 双持时走路 / 攻击 | 依然看不到，画面**不闪**、没有黑三角 |
| 4 | 再按一次双持键回单手 | 盾**立刻回到手里** |
| 5 | 左手道具真正使用时（举盾 / 左手攻击） | 照常显示 |
| 6 | 右手**成对武器单持**（佣兵双刀等） | 身上那把副手刀看不到；双持成对武器时两把都在手里 |

## 如果结果不对：不用重启游戏就能排查

`HideSheathedLeft.ini` 每 **1 秒**重读并重新施加一次（`IntervalSeconds=1`），`HidePoly` 改完存盘**1 秒内生效**（参数会被重写）。
之所以是 1 秒而不是更长：引擎在某些事件（换装备、切区域、参数重载）后会把这几格写回原值，直到 mod 下一遍写入之前，收起的左手道具可能短暂出现一下；这个间隔就是那个窗口的上限。
按现象对照：

| 现象 | 说明 | 下一步 |
|---|---|---|
| 一切正常（第 2 步盾消失、第 4 步恢复） | 停放挂点被引擎接受 | 完成了，告诉我，我做正式版收尾（含成对武器逐个武器核查） |
| 又出现黑三角 / 全屏闪烁 | 参数指向的挂点被判无效（默认 220 应该不会） | 先确认 `chr\c0000.chrbnd.dcx` 被换成了本包的版本（`-Status`，应为 47 KB 左右）；再试 `HidePoly=382`（存盘，1 秒生效）看是否换成另一种表现 |
| 盾跑到腰/背上（回到了可见位置） | 参数没打到引擎在读的那份表（见下），或模型没换 | 先看日志有没有 `applied ...`；再用 `reference\` 里的方法确认哪几份表被打到了 |
| 盾跑到一个奇怪但可见的位置（比如脚边、胸口） | 挂点存在但位置不是"远处" | 那就是在 FLVER 里挪挂点这一步没生效，把 `-Status` 和 `docs/dummies-parked.txt` 发我 |
| 完全没变化（盾照旧挂背上） | 写值没生效 | 看日志里 `applied ... write(s)` 是否为 0；`HideLeftHang` 是否为 1 |
| 游戏起不来 | 多半是 `xinput1_3.dll` 又变回了 DKP 加载器 | 跑 `restore.ps1`，确认 `xinput1_3.dll.dkp-off` 存在 |

## 已知限制（和旧版相同，未变）

- **参数表仍然是 PC/NPC 共用的**：NPC 若进入"左手收起"状态，它的模型也会被挪到那个挂点。DS3 敌人武器常在手，基本不会进这个状态，但这不是严格只对玩家生效（要做到严格玩家限定得 hook 挂点解析函数）。
- 成对武器的右侧模型是**所有武器一起改**（91 行参数一起写）：绝大多数武器没有模型 1–3，无影响。
  担心"刀鞘跟着消失"就把 `PairedFields=1`（只藏副手刀刃）；完全不想动就 `HidePairedOffhand=0`。
- **NPC 通道（已解决到"不可见"）**：所有角色模型都追加了 382/383，敌人进入同一姿态时道具同样被放到
  1 公里下方 —— **没有黑三角、没有穿模、没有变形**。与 vanilla 的唯一差别是：那件道具也不会显示在 NPC 背上。
  要做到"NPC 完全保持原版（道具照旧挂背上）"，只能 hook 挂点解析、把效果限定到玩家的 ChrAsm。
- **模型补丁需要重跑**：换装/模型类 mod 若覆盖了 `chr\*.chrbnd.dcx`，那 382/383 就没了（极端情况回到黑三角）。
  本包 `tools\` 里带了一个补丁器，改完模型后执行一次即可（见下）。
- 联机有服务端存档检查风险，**建议离线**。

## 内存占用（1.0.2 修复）

1.0.1 打开游戏后内存比原版多约 4 GB。原因不是泄漏，也不是参数写入，而是"找参数表"时把进程的**每一个
已提交页都读了一遍**：DS3 启动时就把约 8 GB 资源池 commit 好，主菜单时只有约 1.6 GB 常驻，其余被系统
收进了页面文件；读一个被换出的页会把它**换回物理内存**，于是那 4 GB 变成了真实占用。（`MEM_MAPPED` 还
会把映射进来的 `chr` 文件一起拉回内存。）

1.0.2 改成**只读当前常驻的页**（`QueryWorkingSetEx` 逐页判断，只读连续常驻区间），并且**删掉了所有
"全量读"回退**：表还没常驻就等 1 秒重试，而不是强行把页拽进来。写入逻辑完全没变。

实测（同一起动流程，每 2 秒采样、100 秒）：

| 配置 | 峰值工作集 |
|---|---|
| 原版（ini 里 `LoadCore=0`，不加载本 mod） | 1634 MB |
| 1.0.1 | 6007 MB |
| 1.0.2 | 1624 MB |

开关对比（同一份文件，交替跑 A/B/A/B）：工作集 1613.0 MB（开）vs 1610.5 MB（关），**差 2.5 MB**，
比同一配置两轮之间的抖动还小；日志里 `applied 2548 field write(s) over 364 row(s) in 4 table(s)`
与 1.0.1 完全一致，功能没打折。

自己怎么确认：看游戏目录下的 `HideSheathedLeft.log`——第二行会写版本
`--- HideSheathedLeft 1.0.2 loaded (pid …) ---`，`scan:` 那行的 `read … MB resident` 应该是几十到
几百 MB、`left … MB untouched` 是几个 GB；如果 `read` 是几个 GB，那就是 1.0.1 或更早的版本。

（英文版 `docs\MEMORY-FIX-1.0.2.md`）；测试脚本在 `research\runtime\`。
