Probe mode (Probe=1) — how to capture engine reads
==================================================

What it is
----------
`Probe=1` in `HideSheathedLeft.ini` makes the mod write **nothing** to the game. Instead it:

  * puts `PAGE_GUARD` on the memory pages that hold the `WepAbsorpPosParam` row data of every
    table copy it can find (it re-scans and arms new copies a few times after start-up),
  * installs a vectored exception handler that logs the faulting address, RIP, registers and stack
    for every access, and re-arms the guard with a single-step trap so no access is missed,
  * periodically dumps a `WorldChrMan` pointer map (candidate offset `0x4768E78`),
  * periodically scans memory for the parking dummies 382/383 to locate the loaded player model.

Everything goes to `<game>\HideSheathedLeft.log`. While the probe is active the mod has no effect
on the game (items stay on your back).

What the log lines mean
-----------------------
    HIT attach-field read: row=0x30 off=+0x0 val16=0x0001 RIP=0x140E3174B (exe+0xE3174B) ...
        a read of a parameter row: `row` = row id, `off` = offset inside the row,
        `val16` = the value read, `exe+...` = the reading code

    STACK selector rsp=... rbx=... r10=...      followed by `stack+..` lines
        register + stack dump at the hang-dummy selector (`exe+0xE31690`), used to find the
        caller (and therefore the character) that owns the resolution

    wcm graph base=...   /  wcm+000 -> ...
        candidate `WorldChrMan` structure and the pointers it holds

How to use it (2 minutes)
-------------------------
1. Make sure `Probe=1`, start the game from Steam, load a save (be in the world, able to move).
2. Change equipment a few times — reads of the parameter table happen when a character's attach
   data is rebuilt:
     * swap the right-hand weapon out and back,
     * swap the left-hand item (shield <-> something else),
     * two-hand the right-hand weapon, wait 2 s, release (3 times),
     * block/swing once with the left hand.
3. Quit and read `<game>\HideSheathedLeft.log`.

Findings from the last two sessions (2026-10-14)
-----------------------------------------------
* Many parameter-table copies exist in memory (up to 6 armed at once, 546 rows, 20 pages). The
  engine's live copy is not always among the ones found first, which is the same root cause as the
  documented "silent no-op".
* During normal play the engine barely reads that table at all: the resolved attach values are
  cached per character, so a 2-minute session with equipment swaps produced **zero** hits.
* The reads that were captured came from the parameter accessor wrapper
  (`exe+0xE350D0`, unique selector call site `exe+0xE35125`) and from bulk table scans
  (`exe+0x1FC358F`, `exe+0xE318F4`), not from a per-frame draw path.
